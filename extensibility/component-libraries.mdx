---
title: "Component libraries"
description: "Organize reusable PSX components into importable Python packages."
---

A **component library** is a collection of UI pieces that other applications can import. Think of a toolbox: each component is a tool, and the Python package is the toolbox. **A library is not automatically a plugin.**

## From one file to a library

A simple project can start like this:

```text
monitoring-ui/
├── pyproject.toml
├── src/
│   └── monitoring_ui/
│       ├── __init__.py
│       └── status_card.py
└── demo.py
```

`status_card.py` defines the component; `__init__.py` re-exports it so consumers can write `from monitoring_ui import StatusCard`. The consuming application decides how to make the component visible to its PSX compiler.

## A minimal reusable component

```python
# src/monitoring_ui/status_card.py
from velto.ui import component, psx


@component
def StatusCard(message: str):
    return psx("""
        <Flex direction="column" gap="4">
            <Text>Status</Text>
            <Text>{message}</Text>
        </Flex>
    """)
```

```python
# src/monitoring_ui/__init__.py
from .status_card import StatusCard

__all__ = ["StatusCard"]
```

This is a **library-definition example**, not a claim that any template can use `<StatusCard>` without explicit scope or registration.

## Reuse versus registration

| Reuse | Registration |
| --- | --- |
| Python imports a function/class | A registry maps a string name to a constructor |
| Useful for ordinary libraries | Useful for explicitly compiled templates and plugin ecosystems |
| Does not require plugin discovery | Requires passing the correct registry to the compilation path |

For the verified registry example, continue to [Component registration](/extensibility/component-registration).

## Can it work on all backends?

A component made only of standard PSX elements is **potentially portable**. A component that embeds `QWebEngineView` is **Qt-specific**. Packaging does not erase toolkit requirements.

## Distribution

You can install your library locally with `pip install -e .`, from a Git repository, or from PyPI. These installation methods distribute Python code; they do **not** automatically register PSX names. See [Publishing your extension](/extensibility/publishing-your-extension).
