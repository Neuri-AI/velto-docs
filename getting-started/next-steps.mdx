You've reached the end of **Getting Started**. You now have a working Velto application, and you've learned how to build and organize its interface using Python and PSX Markup.

You don't need to understand the entire framework before building something useful. The next step is to choose the part of Velto that helps you make progress on your own application.

## What you've accomplished

Let's look back at what you've built:

1. In [Install Velto](/getting-started/installation), you prepared your environment.
2. In [Hello World](/getting-started/hello-world), you opened your first native application window.
3. In [Your first component](/getting-started/first-component), you created a reusable `Welcome` component and passed data into it.
4. In [Your first interaction](/getting-started/first-interaction), you connected a button click to Python code and updated the interface using `use_state`.
5. In [Project structure](/getting-started/project-structure), you explored the files and folders generated by Velto CLI and learned where to organize your code.

You've already used the essential building blocks: **components, PSX Markup, props, events, and local state**.

Now let's explore where to go next.

## 1. Understand components and state

**Start here if you want to understand why your existing code works and how to build more reusable interfaces.**

The [Fundamentals](/fundamentals/components-props-children) section builds on your first components without assuming you know the internals of a UI framework.

A useful reading order is:

1. [Components, props, and children](/fundamentals/components-props-children) — Pass data and nested interface content between components.
2. [Events and local state](/fundamentals/events-and-local-state) — Go beyond a simple counter and understand how interactions update the UI.
3. [Effects and refs](/fundamentals/effects-and-refs) — Learn when components need to interact with things outside their rendered content.
4. [Conditional and dynamic UI](/fundamentals/conditional-and-dynamic-ui) — Display different content as your application's data changes.
5. [Keys and identity](/fundamentals/keys-and-identity) — Understand how Velto identifies elements when the interface changes.

You don't need to read all five pages before continuing. Start with the concept that matches what you're trying to build.

## 2. Get comfortable with PSX Markup

**Choose this path if you can write a component but want to express more complex interfaces confidently.**

You've already written markup like this:

```python
return psx("""
    <Flex direction="column" gap="12px">
        <Text>Welcome to Velto!</Text>
        <Button on_click={increment}>Increment</Button>
    </Flex>
""")
```

PSX Markup is how you describe the structure of your interface. The [PSX Markup overview](/markup/overview) introduces the language in more detail.

From there, explore:

- [Syntax, elements, and text](/markup/syntax-elements-and-text) to understand the building blocks of markup.
- [Attributes, props, and interpolation](/markup/attributes-props-and-interpolation) to pass values and display Python data.
- [Custom components and composition](/markup/custom-components-and-composition) to combine your own components.
- [Conditional rendering](/markup/conditional-rendering) and [Lists and keys](/markup/lists-and-keys) when your interface needs to change based on data.

You can return to these pages whenever you encounter a new markup pattern.

## 3. Build more useful interfaces

**Choose this path if you're ready to move beyond greetings and counters.**

Velto includes UI components and layout tools for building application interfaces.

Start with [Build interfaces](/ui/overview) to discover available UI elements. Then explore the parts most relevant to your project:

- [Text, actions, and feedback](/ui/text-actions-and-feedback) for labels, buttons, and feedback.
- [Inputs and selection](/ui/inputs-and-selection) for collecting information from users.
- [Containers and scrolling](/ui/containers-and-scrolling) for organizing larger interfaces.
- [Layout overview](/layout/overview), [Flex](/layout/flex), and [Grid](/layout/grid) for controlling how elements are arranged.

You don't need to memorize every component. Find one that solves the next problem in your application, try it, and build from there.

## 4. Explore application state when you need it

Your counter used `use_state()` to remember a number inside one component. That's a good fit for small, local interactions.

As an application grows, different parts of its interface may need to work with shared information. Velto integrates **Pydux** for more structured application state management.

When you reach that point, start with [State overview](/state/overview). You can learn about stores, slices, selectors, and other tools as your application requires them.

**For now, keep using local state when it's enough.** You don't need a shared store just to make a button work.

## 5. Learn about the application runtime and configuration

You've been running your application with Velto CLI and letting `VeltoContext` handle the application lifecycle.

When you want to understand configuration, native framework integration, or preparing an application for distribution, explore the corresponding runtime and tooling documentation.

Remember that your application's window settings belong in its configuration files, not in a `<Window>` element inside PSX Markup. The `settings/` folder you saw in [Project structure](/getting-started/project-structure) is the starting point for that configuration.

There's no need to configure packaging or signing while you're still learning basic UI development.

## A small project to practice

Before diving into every reference page, try turning your counter into a small **click tracker**.

Keep the `Welcome` component and expand `Counter` so that it:

1. Displays the current number.
2. Provides **Increment**, **Decrement**, and **Reset** buttons.
3. Starts at a value you choose.
4. Lives in `components/counter.py`, imported by `main.py`.

This exercise uses only concepts you've already encountered. If you get stuck, revisit [Your first interaction](/getting-started/first-interaction) and [Project structure](/getting-started/project-structure).

Once it works, try adding an input or another layout from the UI documentation.

## Keep building

You now know enough to create a small native application with Velto. The best way to continue is to **build something, look up the next concept you need, and improve it one piece at a time**.

If you're unsure where to begin, we recommend [Components, props, and children](/fundamentals/components-props-children). It picks up directly where your first component lesson left off.

You can always return to [Getting Started](/getting-started/overview) whenever you want to revisit the basics.
