---
title: "Native widget integration"
description: "Use external toolkit widgets with a stable reactive props contract."
---

`Native` integrates Qt, Tkinter, Kivy or third-party widgets **without
converting their framework**. Choose a matching runtime backend.

## 1. Mount an existing widget

```python
from PySide6.QtWebEngineWidgets import QWebEngineView
from velto.ui import psx
```

```jsx
<Native widget={QWebEngineView}
        width="100%" height="100vh" key="browser" />
```

A widget with no reactive `props` needs no adapter. A class/factory is
created and owned by PSX; passing an existing instance borrows it.

## 2. Write a custom class using update_props

```python
from PySide6.QtCore import QUrl
from PySide6.QtWebEngineWidgets import QWebEngineView

class Browser(QWebEngineView):
    def update_props(self, props, changed):
        if "url" in changed:
            url = props["url"]
            if url and not url.startswith(("http://", "https://")):
                url = "https://" + url
            if url:
                self.setUrl(QUrl(url))
```

```jsx
<Native widget={Browser}
        props={{"url": current_url}}
        width="100%" height="100vh" key="browser" />
```

`update_props(self, props, changed)` receives all current reactive props and
a `frozenset[str]` naming only changed/new keys. Velto doesn't guess setters
based on property names.

## 3. Adapt a third-party class

```python
import pyqtgraph as pg
from velto.ui import native_adapter

@native_adapter(pg.PlotWidget)
def update_chart(widget, props, changed):
    if not hasattr(widget, "_curve"):
        widget._curve = widget.plot()
    if "data" in changed:
        widget._curve.setData(props["data"])
```

```jsx
<Native widget={pg.PlotWidget}
        kwargs={{"background": "#151515"}}
        props={{"data": cpu_values}}
        width="100%" height="400px" key="chart" />
```

An external adapter is registered once, and applies to subclasses unless a
more specific adapter exists. If the widget itself implements `update_props`,
that method takes precedence. Never mutate `props` within the handler.

## 4. Constructor configuration versus reactive values

`args` and `kwargs` go to the constructor; `props` is passed to the
update handler after mounting and on changes. Changed constructor arguments
remount only the native widget; changed reactive props preserve it.

PSX uses shallow/identity-safe comparisons to avoid expensive comparisons of
NumPy arrays during resize. Supply new arrays/objects when their contents
change. Removing a reactive property key currently raises an error; use a
reset value (e.g. `None`) that your handler supports.

Layout-related `width`, `height` and CSS stay under Cinnamon's control.
All widget operations run on the renderer's UI thread; no worker threads
are used for applying props.

## 5. Ownership and compatibility

| Passed widget | Ownership | Unmount |
| --- | --- | --- |
| Class or factory | Owned | PSX releases it |
| Existing instance | Borrowed | Caller retains lifetime |

Tkinter cannot change a widget's master; borrowed widgets must respect
backend restrictions. Qt, Tkinter and Kivy have different native API surfaces.
Only use widgets compatible with the selected renderer.

For specialized lifecycle control, use the low-level `NativeWidget`
declaration and its `update`, `bind_event` and `sfle_port` callbacks.
See [Native component reference](/reference/ui/components/native).
