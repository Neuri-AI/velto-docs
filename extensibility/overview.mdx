You already know how to write a PSX component. Imagine you want to share it with your team, make it available in another application, or use a native control that PSX does not provide. **That is what extending Velto means.**

We will learn by building **one project**, `velto-controls`, rather than introducing a dozen unrelated APIs. The first version uses only familiar `@component` and hooks. Later we will see why renderers, adapters, registries and plugins exist.

## The destination

At the end of the course, we want a reusable `CounterCard` with a consistent public interface, supported by Qt, Tkinter and Kivy *when its backend implementations have been built and registered*. We also want to package and share it with other developers.

## Start with the simplest tool

| You want to... | Learn... |
| --- | --- |
| Reuse a piece of PSX UI | Component composition |
| Understand how a tag becomes a widget | PSX rendering pipeline |
| Embed an existing toolkit widget | Native integration |
| Support a new native node type | Renderer adapter |
| Make a custom name available to PSX | Component registration |
| Group extension registration | PluginAPI |
| Share your work | Packaging and PyPI |

**No prior knowledge of renderer internals is required.** We will define every new term at the moment it becomes useful.
