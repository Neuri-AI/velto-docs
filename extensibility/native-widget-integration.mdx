---
title: "Native widget integration"
description: "Embed existing toolkit widgets and understand ownership and compatibility."
---

Sometimes you do not need to build a widget: **Qt, Tkinter, or Kivy already has it**. The `Native` integration lets a PSX tree include that control when the renderer is compatible.

## A simple mental model

PSX describes **where the widget belongs** in the interface. The toolkit supplies **what the widget actually is**. Putting a Qt widget inside PSX does not convert it into a Kivy widget.

## An existing Qt plot

```python
import pyqtgraph as pg
from velto.ui import psx


class MetricsPlot(pg.PlotWidget):
    def __init__(self):
        super().__init__()
        self.plot([2, 5, 3, 7, 4])


def chart_view():
    return psx("""
        <Flex width="100%" height="100%">
            <Native widget={MetricsPlot} />
        </Flex>
    """)
```

This is an **integration fragment**, not a complete runnable application. It needs PyQtGraph, a matching Qt binding, and a compatible renderer. Confirm that the active markup compiler can resolve `MetricsPlot` from the Python scope.

## Who owns the widget?

| You provide | Ownership | On unmount |
| --- | --- | --- |
| A widget class or factory | **Owned** by PSX | PSX creates and releases it |
| An existing widget instance | **Borrowed** | PSX must not destroy the caller-owned widget |

The documented lower-level `NativeWidget` declaration requires a factory with `ownership="owned"` or an instance with `ownership="borrowed"`; providing both is invalid.

**Backend differences matter:** Qt borrowing restores the previous parent; Kivy borrowing restores parent and relevant layout hints; borrowing an existing Tkinter widget is unsupported because its master is fixed at creation.

## What about updates and events?

The lower-level native contract supports an `update(widget, changed, removed)` callback and `bind_event(widget, event, slot)` returning cleanup. PSX can update the existing control instead of rebuilding it. Layout and measurement still matter; geometry bridges handle common widgets, while advanced cases may require an explicit `sfle_port`.

## When should I write an adapter instead?

Use [Renderer adapters](/extensibility/renderer-adapters) if `Native` cannot express the native lifecycle you need. Otherwise prefer reusing the existing toolkit widget. See [Build a native chart](/extensibility/build-a-native-chart) and [Embed a web browser](/extensibility/embed-a-web-browser).
